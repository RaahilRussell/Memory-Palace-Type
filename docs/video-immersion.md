# Video immersion

An uploaded or archived MP4, WebM, or MOV can play on a moving 3D depth surface. The original video supplies color and motion continuously. Depth Anything V2 estimates 2–8 keyframes across the whole recording, and the browser updates the geometry as playback advances or is scrubbed. Stable surfaces interpolate; large depth changes switch at the closest sample to avoid stretching across cuts and occlusions. Local instance segmentation supplies sampled person masks, which render as a separate moving depth surface over a clean plate from the first frame.

Each keyframe also runs common-object recognition. Recognized objects use the same closed category meshes as photo memories, with photographed colors and front markings. Video props follow the nearest sampled frame and cannot be picked up; photos allow pickup. A validated `trackedObjects` sequence can add a continuously animated rigid circular tin, with camera-space position, apparent depth, and rotation keyframes; its silhouette is removed from sampled person and room surfaces so the mesh remains distinct. These layers are still a bounded single-camera reconstruction, not a volumetric scan: unseen views of the person are not recovered, and rapid movement can reveal mask or depth changes between the 2–8 samples.

Video completion runs local person instance segmentation alongside local object recognition. Photo-only pose fitting and generated rear atlases remain disabled. A stationary camera with an empty opening frame works best: the first sampled image becomes the fixed background plate, while each person mask and tracked tin gets its own scene object.

The Mint actor path also analyzes every source frame, up to 2,000 decoded frames, for denser mask and depth motion. Longer clips retain sampled reconstruction without dense actors. The fixed background assumes a stationary camera and an empty opening frame; otherwise ghosting or repeated image details can remain. This is single-camera 2.5D and does not recover hidden scenery. See [moving memories](video-and-memory-objects.md#step-into-video) for the dense actor limits.

The server needs `ffmpeg` and `ffprobe` on PATH, or explicit `FFMPEG_PATH` and `FFPROBE_PATH` values. Extraction is local-only, uses `execFile` without a shell, disables network protocols, and limits each frame to 512 pixels on its longest edge. Browser depth grids are at most 128×128 vertices. Existing 50 MB upload limits apply; recordings longer than one hour are rejected.

Cache keys hash the entire original video, so replacing motion while retaining the same opening frame cannot reuse stale depth. All frame artifacts and ordered timestamps are checked before cached metadata is returned. Video-stream duration takes priority over container duration because an audio tail can extend beyond the final image.

The API runs depth generation in one disposable child process, then completes each sampled frame in its own child. Jobs are serialized across scene requests, and each child exits before the next starts so native model memory is reclaimed. Video completion uses local person segmentation and object recognition; photo-only pose fitting and generated texture atlases are not used. The API can serve health checks and the original video while reconstruction runs. Identical pending scene requests share the work.

`SCENE_INFERENCE_TIMEOUT_MS` defaults to 1800000 milliseconds per worker; the entire video can take several workers' worth of time. A timeout or unavailable object detector fails the request. Each successful frame is cached, so retrying reuses finished work. All sampled frames must complete recognition before a scene is returned, although a successful recognition pass can contain no supported objects. See [runtime isolation and retries](reconstruction.md#runtime-isolation-and-retries) for configuration and diagnostics.

Sampling is uniform over the recording, capped at eight frames even for a long clip. A short event between samples can therefore be absent from depth and recognition while remaining visible in the continuous video texture. Ordinary props are detected independently per sample. Validated tracked-object sequences retain their continuous motion separately. Completion of every sample means the current depth-and-props pipeline finished, not that camera motion, unseen surfaces or a full volumetric performance were recovered.

Tests cover video-file replacement, missing later-frame artifacts, timestamp and path validation, bounded sampling, audio tails, per-frame recognition, scrubbing/looping, actual vertex movement, discontinuity handling, backing-layer alignment and cleanup, point-cloud visibility, worker failures and timeouts, and API/media responsiveness during synthetic inference. The same renderer is used in desktop, mobile, and WebXR views; hardware performance and controller behavior still need a connected Quest test.
